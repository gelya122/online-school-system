# Чек-лист ручного тестирования desktop-админки

Перед прогоном: запущен backend API, в `appsettings.json` указан корректный `Api:BaseUrl`, есть учётные записи ролей **admin**, **manager**, **teacher**.

Логи приложения: `%LocalAppData%\online_school_admin\logs\`.

---

1. **Регистрация сотрудника** — «Регистрация сотрудника», заполнить форму, сохранить; войти под новым пользователем (если политика допускает).
2. **Авторизация** — вход admin/manager/teacher; студент не должен входить в админку.
3. **Создание студента** — Студенты → Добавить; проверить валидацию полей и успешное сохранение.
4. **Создание курса** — Курсы → Добавить шаблон; проверить сохранение и открытие карточки.
5. **Блоки и уроки** — Карточка курса → структура: блоки, уроки, материалы, порядок.
6. **ДЗ** — Урок → вкладка ДЗ: создание, задания, ответы, порядок.
7. **Поток** — Потоки → Добавить, сохранить; список и карточка потока.
8. **Запись на поток** — Карточка потока → студенты: одиночная и массовая запись; лимит мест.
9. **Сдача и проверка ДЗ** — Студент сдаёт в LMS (или тестовые данные); Проверка ДЗ: очередь, детали, баллы, статусы.
10. **Прогресс** — Прогресс студентов: список, детализация по записи.
11. **Заявка** — Заявки: создание/редактирование, статусы, комментарии.
12. **Конвертация заявки** — Детали заявки → создать студента; проверить появление в списке студентов.
13. **Заказ** — Платежи → заказы → создать заказ.
14. **Промокод** — применить промокод к заказу (роль admin или сценарий с правами manager на просмотр).
15. **Уведомление** — Уведомления: одному пользователю и/или потоку; удаление с подтверждением.
16. **Аналитика** — периоды, загрузка без ошибок, корректность чисел.

Дополнительно: обрыв сети (остановка API) — понятное сообщение; истечение JWT — возврат на экран входа; экспорт CSV на страницах Студенты и Потоки; подтверждения архивации/удаления.
